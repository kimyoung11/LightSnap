# 다른 LLM / 개발자에게 인계하기

## 문서의 기준

0.2.0 코드 기준으로 작성했습니다. 대화 기록이나 특정 AI 서비스 계정 없이 이 저장소만으로 개발을 이어가는 것이 목표입니다. 현재 동작은 소스를 우선하고, 제안 문서를 이미 구현된 기능으로 해석하지 마세요.

## 현재 구현과 미구현

구현: 2·4·6분할, ⅓·⅔, 최대화·복원, 단축키 편집·저장, 메뉴 상주·일시정지, 다음 화면 이동, 좌우 크기 순환, 로그인 실행 설정, 로컬 리소스·지연 진단.

미구현: 여백, 앱별 제외, 사용자 레이아웃, 드래그 오버레이, 작업 공간 프리셋, 자동 업데이트, 정식 배포 파이프라인, 지속적인 구조화 로그, 진단의 자동 익명화, CI 비밀정보 스캔.

기본 빌드는 ad-hoc 서명이다. 인증서 서명 선택은 가능하지만 공증과 인증서 관리 자동화는 없다. 저장소 라이선스는 아직 미지정이다. 공개 범위·라이선스·가격·계정 연결 변경은 현재 요청에 없는 제품 결정으로 취급한다.

## 확인된 증거와 한계

- 0.2.0의 427개 assertion 및 macOS CI 빌드·서명 검사가 통과했다. 향후 변경에서는 직접 다시 실행하고 최신 결과를 기록한다.
- 0.1.2에서 실제 사용자가 접근성 권한 초기화·재연결 후 기본 스냅이 작동함을 확인했다.
- 0.2.0의 다중 모니터 실제 이동, 로그인 항목 승인·로그인 재실행, 설정 UI는 수동 확인이 남아 있다.
- 메모리 50 MB 이하와 스냅 50 ms 미만은 목표이지 실측 보장이 아니다.

## 이전에 발생한 문제

단축키는 수신되지만 AX 권한이 미연결인 상태에서 설정창이 반복해서 앞으로 나왔다. 현재는 자동 팝업을 제거하고 권한 차단을 메뉴 상태에 표시한다. ad-hoc 재빌드나 다른 경로의 앱 복사본 때문에 허용한 앱과 실행 앱이 달라질 수 있다.

문제 분석은 ‘입력 수신 → 권한 → 대상 창 → AX 쓰기 → 결과 확인’ 순서로 한다. 단순히 새 바이너리를 반복 전달하면 서명이 바뀌어 권한 문제를 더 복잡하게 만들 수 있다. 권한 우회, 전체 TCC 초기화, 서명 검증 완화로 해결하지 않는다. 필요한 경우 README의 앱 ID에 한정한 재연결 절차를 사용한다.

## 그대로 전달할 시작 프롬프트

```text
이 저장소의 AGENTS.md, README.md, docs/HANDOFF.md,
docs/ARCHITECTURE.md, docs/DEVELOPMENT.md를 읽어 주세요.
현재 git 상태와 실제 소스를 확인한 뒤 다음 작업을 구현해 주세요.

작업: [원하는 기능 또는 버그의 재현 단계]
완료 조건: [사용자에게 보여야 할 결과]

기존 단축키·해제 상태와 복원 동작을 보존해 주세요.
메인 UI 스레드에서 다른 앱의 AX 호출을 실행하지 마세요.
코드 변경에 맞는 검사와 문서를 갱신하고, 실제 실행하지 않은 검증은
미검증으로 구분해 주세요. 보안·배포·로그 기능은 제안과 현재 구현을
구분해 주세요. 마지막에 변경 내용, 수행한 검증, 남은 위험을 알려 주세요.
```

## 한 작업을 마칠 때 남길 인계 기록

```text
기준 버전 / 커밋:
해결한 사용자 문제:
주요 변경 파일:
저장 형식 / 마이그레이션 영향:
자동 검사와 실제 실행 결과:
미확인 OS·앱·화면 조합:
개인정보·권한·리소스 영향:
다음으로 할 일:
```

코드나 문서에 자격증명·개인 진단 원본을 복사하지 않는다. 사용자가 내보낸 진단은 비공개 환경에서 먼저 검토하고 공개용 사본은 별도로 익명화한다.
