# 기능 확장 제안

아래는 제안이며 아직 구현되지 않았다. 현재 0.2.0의 모니터 이동·자동 실행·좌우 크기 순환은 완료된 기능이므로 다시 개발할 항목에 넣지 않는다. 버전 구분은 계획 예시이며 확정 일정이 아니다.

‘창 중앙 배치’는 현재 SnapEngine이 이동·크기 변경 둘 다 가능해야 한다는 조건을 그대로 재사용하면 고정 크기 창에서 실패한다. 이처럼 기존 제약을 먼저 확인하고 기능별 연산 권한을 분리해야 한다.

## 추천 묶음

- **다음 작업:** 진단 자동 익명화·비밀정보 검사·단일 버전 원본과 함께 F01 여백, F02 제외 앱.
- **그 다음:** 설정 UI 정리, F03 중앙 배치, F04 방향별 모니터 이동.
- **이후:** 사용자 레이아웃. 데이터 마이그레이션과 편집 UX를 먼저 확정.
- **마지막:** 프리셋·드래그 오버레이. 권한·실패 복구·리소스 복잡도가 커진다.

## 서로 충돌하는 요구 먼저 결정하기

1. 여백은 화면 바깥 여백과 창 사이 여백을 구분한다. 두 창 사이에 같은 값을 두 번 적용하지 않도록 공유 경계 정책을 정한다.
2. 모니터 이동 시 기존 여백을 포함한 창 비율을 옮길지, 논리 레이아웃을 다시 적용할지 결정한다.
3. 순환 판단은 사용자가 선택한 논리 배치를 기준으로 유지하고 여백 변경 후에는 상태를 초기화한다.
4. 앱 제외는 사용자가 직접 선택한 앱으로 관리한다. 모든 앱의 창 제목을 상시 수집하지 않는다.
5. 프리셋을 위해 ‘다른 앱 자동 실행’이 필요하다면 창 이동과 구분해 설정과 결과에 표시한다.

## 모든 기능의 공통 완료 기준

- 기존 단축키·해제·최초 복원을 유지하고 필요한 마이그레이션을 검사한다.
- 권한 없음·전체 화면·최소 크기·앱 응답 지연·화면 분리에서 성공을 잘못 표시하지 않는다.
- AX 작업은 직렬 큐, UI는 메인 스레드, 무제한 이벤트 큐·이력·로그를 만들지 않는다.
- 자동 검사, 관련 실제 앱 수동 확인, README/CHANGELOG/VALIDATION을 함께 갱신한다.
- 추가 권한·외부 연결·개인정보·지속 작업이 생기면 제품 화면과 보안 문서에 반영한다.
