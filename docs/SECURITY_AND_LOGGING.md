# 보안·로그·운영 보완 제안

이 문서는 0.2.0 구현을 점검한 제안이다. 아래 목표 기능은 아직 구현되지 않았다. 앱은 현재 원격 서버·외부 API·자동 로그 업로드를 사용하지 않는다.

## 현재와 차이

| 항목 | 현재 | 필요한 보완 |
| --- | --- | --- |
| 소스 비밀정보 검사 | 업로드 전 수동 패턴 검사, gitignore | 변경분·전체 이력 전용 스캔 및 CI 차단 |
| 진단 내보내기 | 사용자 저장, 자유 notes에 경로/PID/앱 이름 | 기본 익명화, schemaVersion, 저장 전 미리보기 |
| 오류 정보 | 결과 상태·사람용 메시지 | 안정적인 errorCode와 원인 AXError/OSStatus |
| 로컬 로그 | 카운터·최근 100회 지연, 지속 Logger 없음 | 개인정보 제한 구조화 이벤트, 레벨·상한·내보내기 정책 |
| 배포 | ad-hoc 또는 선택한 인증서 서명 | 정식 서명·공증·최종 ZIP 무결성·설치 검증 |
| CI | 읽기 권한·고정 checkout SHA·인증정보 비지속 | 보안 스캔·의존 Action 업데이트·아키텍처 검사 |

## 권장 순서와 완료 조건

### S01 — 기본 익명화 진단 (최우선)

공개 이슈에 진단 파일을 붙일 때 사용자가 직접 경로를 지우는 방식에 의존하지 않는다. 현재 notes 문자열은 원본 개인정보를 포함할 수 있다.

- 공개용 기본 출력에서는 전체 경로·사용자명·PID·앱 이름·창 제목·문서 URL을 제외한다.
- 기술적으로 필요한 앱 식별값도 기본 비공개로 하고, 필요 시 사용자가 개별 공개를 선택한다. bundle ID도 사용 앱 목록을 드러낼 수 있다.
- 상세 원본은 별도 명시적 선택과 미리보기를 거친다. ‘로그 저장’ 선택을 ‘업로드 동의’로 해석하지 않는다.
- 경로를 무조건 해시하는 것을 익명화라고 가정하지 않는다. 필요 없는 필드는 수집/출력하지 않는 편이 낫다.
- 저장 취소 시 파일을 만들지 않으며, 자유 notes에 원본 정보가 다시 들어가지 않도록 구조화 필드로 바꾼다.
- 테스트용 가상 사용자명·경로·앱 이름을 넣어 기본 JSON·텍스트·로그 모두에 남지 않는지 검사한다.

### S02 — 비밀정보 스캔과 변경 보호 (최우선)

전용 스캐너(예: Gitleaks)를 검토하여 커밋 직전 변경분과 CI의 Git 이력을 검사한다. 도입 시 공식 저장소의 현재 버전·명령·라이선스를 확인한다. 아직 CI에 추가하지 않았다.

- 바이너리 개인키·인증서·PAT·클라우드 키 등도 검사 범위에 포함한다. gitignore는 검사의 대체물이 아니다.
- 최소 권한으로 동작하고 탐지 결과에서 실제 비밀값은 마스킹한다. 원본 탐지 내용을 공개 artifact로 올리지 않는다.
- 테스트 fixture의 예외는 정확한 경로·규칙과 사유로 좁히고 저장소 전체를 제외하지 않는다.
- 샘플 탐지 검증은 실제 자격증명을 생성하지 않고 합성 fixture로, 운영 main 이력 밖에서 수행한다.
- 전체 이력 검사와 변경분 검사를 구분한다. 과거에 유출된 값이 발견되면 먼저 폐기·교체하고 이후 이력 정리를 계획한다.
- CI가 ‘실행됐으나 읽을 이력 없음’인 상태를 통과로 오해하지 않도록 checkout 범위를 설정한다.
- branch/ruleset의 필수 검사, 유지관리자 권한, 비공개 취약점 제보 설정은 지원 여부·계정 플랜을 확인한 뒤 별도 적용한다.

참고: [Gitleaks 공식 저장소](https://github.com/gitleaks/gitleaks), [GitHub Actions 보안 지침](https://docs.github.com/en/actions/reference/security/secure-use).

### S03 — 구조화 로컬 로그와 오류 분류

Swift `Logger` / OSLog를 우선 검토한다. 자체 무제한 파일 로그와 자동 전송을 처음부터 추가하지 않는다. 예시 subsystem은 `dev.lightsnap.mac`, category는 `permission`, `hotkey`, `snap`, `login`, `lifecycle`이다.

| 이벤트 제안 | 기본 허용 정보 | 기본 제외 정보 |
| --- | --- | --- |
| permission.denied | 오류 코드, 권한 연결 여부 | 실행 전체 경로·사용자명 |
| hotkey.registration_failed | 액션 ID, OSStatus | 개인 단축키 원문을 포함한 설정 전체 |
| snap.finished | 요청 ID, 액션 ID, 상태, 소요 ms | 앱/창 이름·문서명·화면 이미지 |
| snap.ax_failed | 단계, AXError 코드, 소요 ms | 읽은 AX 속성 전체 |
| login.registration_failed | 작업 종류, 오류 domain/code | 인증서·개인키·인증 응답 |

단계별 실패 코드를 결과 모델에 추가한다. 예: permissionDenied, noFocusedWindow, fullScreen, moveUnsupported, resizeUnsupported, axTimeout, writeFailed, readbackUnavailable, sizeConstrained, noOtherDisplay. 사용자가 읽는 한국어 문자열로 분기하지 않는다. AX 래퍼가 원인 코드를 버리지 않도록 먼저 수정해야 한다.

로그 레벨은 오류(error), 상태 전환(info), 문제 분석(debug)으로 나눈다. 정상 스냅마다 지속 info 로그를 남기기보다 최근 항목/집계를 활용한다. 반복 권한 오류는 첫 발생과 상태 변화 위주로 기록하고 억제 횟수를 집계한다. 민감값은 보간 시 `.private`를 명시하고 기본 메시지 자체에도 원본을 넣지 않는다. OSLog의 시스템 보관 정책과 별개로 앱이 직접 저장하는 지원 번들은 크기·항목 수 상한을 둔다.

참고: [Apple 로그 생성](https://developer.apple.com/documentation/os/generating-log-messages-from-your-code), [OSLogPrivacy](https://developer.apple.com/documentation/os/oslogprivacy).

### S04 — 지표 누락 보완

현재 권한 미연결·일시정지·busy에서 엔진 호출 전 반환하면 SnapMetrics에 포함되지 않는다. 성공 0회일 때 요약에 실패 개수도 충분히 보이지 않는다.

- 입력 소스(메뉴/단축키), received, accepted, permissionBlocked, paused, busyDropped, success, constrained, failed를 구분한다.
- 카운터 정의를 고정해 한 요청을 여러 실패로 세지 않는다. 의도적으로 버린 반복 입력도 무시된 이유를 분석할 수 있게 한다.
- 성공이 0회여도 실패·차단 횟수와 마지막 오류 코드를 표시한다.
- 성공 p50/p95/p99와 전체 시도 결과를 함께 제시하고 표본 수가 작으면 한계를 표시한다.
- 현재 시간 측정은 렌더링 완료가 아니라 AX 결과 확인이다. 측정 이름에 이 한계를 유지한다.
- 메모리·CPU 장시간 측정은 별도 opt-in 모드로 하고 기본 대기에 타이머를 늘리지 않는다.

### S05 — 진단 스키마와 데이터 수명

DiagnosticExport에 schemaVersion, 앱 버전·빌드, redacted 여부, 측정 모드·단위·범위, 제한된 이벤트 배열을 추가한다. notes 자유 문자열을 필수 진단 계약으로 쓰지 않는다. JSON 가져오기는 아직 없으므로 추후 도입할 때 미래 버전·크기 제한·필드 허용 목록을 검사한다.

기본 최근 로그는 메모리의 제한된 링 버퍼로 제안한다(예: 200개). 파일 로그가 필요해지면 opt-in, 크기·기간 상한, 지우기 버튼, 삭제 정책을 함께 구현한다. 원격 크래시/분석 서비스 도입은 별도 개인정보·동의·네트워크 설계 작업이다.

### S06 — 설정 손상과 미래 버전 보호

단축키 version 값에 따른 명시적인 호환성 판단, 원본 백업, 손상 시 안내, 가져오기 실패 시 원자적 복구를 추가한다. 읽을 수 없는 미래 형식을 기본값으로 덮어쓰지 않는다. 마이그레이션 테스트에 해제된 조합, 중복, 알 수 없는 액션, 손상된 값, 다운그레이드 시도를 포함한다.

## 운영 원칙

관리자 비밀번호·접근성 권한 우회·전체 키 입력 수집·서명 검증 완화로 문제를 해결하지 않는다. 공개 자료에는 진단 원본 대신 익명화된 재현 조건과 안정적인 오류 코드를 사용한다. 위 제안을 구현하기 전에는 ‘자동 익명화/보안 스캔 완료’로 표시하지 않는다.

## Windows 0.1.0 현재 구현

Windows판은 `RegisterHotKey`의 등록된 조합만 수신하며 전역 키보드 훅으로 전체 입력을 수집하지 않는다. 계정·API 키·네트워크 요청·원격 측정·지속 로그가 없다. 요청 시 진단에는 자기 프로세스 메모리, 수신/성공/실패 수, 최근 성공 최대 100회 p95와 일반 상태만 표시한다. 설정은 LocalAppData, 자동 실행은 사용자가 선택할 때 HKCU Run 값 하나를 사용한다. 실행 파일 경로가 사용자 레지스트리에 남으므로 삭제 전 자동 실행을 해제한다.

manifest는 asInvoker/uiAccess=false다. 관리자 앱의 제한을 자동 권한 상승이나 보안 기능 비활성화로 우회하지 않는다. 복원은 HWND+PID+스레드와 창 파괴 이벤트로 정리하고 128개로 제한한다. 파괴 이벤트 대기 집합이 상한을 넘으면 복원 이력을 비워 재사용된 핸들에 잘못 복원하는 위험을 줄인다. 진단/설정에 창 제목·실행 앱 경로를 저장하지 않는다. 이 파일과 설정 파일은 다른 Windows 소프트웨어와 마찬가지로 같은 사용자 권한에서 읽을 수 있으며 별도 암호화는 하지 않는다.

테스트 ZIP은 Authenticode 서명이 없다. 서명 인증서·개인키·자동 업데이트·설치 프로그램은 현재 미구현이며 정식 배포 준비와 구분한다.
